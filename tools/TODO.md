# 待修问题

## 音标补齐的交互问题（v1.1.3 发现，下次更新时修）

用户现象：设置页点「为 53 个单词获取音标」后，屏幕上叠了 **3 条一样的提示**「音标补齐：仍缺 53」，而且按钮上的数字没变。

### 原因一：离线词典本身有 18.65% 词条没音标

`data/dict.json.gz` 的 58,226 条里，有 **10,861 条（18.65%）音标为空**，都是一些非常用词
（`abandoning`、`abbreviated`、`abdallah` 这类变形词或专名）。
所以 1000 个词里剩 53 个补不上，**数据层面是正常的**。

### 原因二：在线补充没生效，但没告诉用户

这些词离线查不到时会去问 dictionaryapi.dev。手机没连 VPN 时该域名连不上，
`fetchPhonetics` 里在线失败只是静默跳过，只在 `stillMissing` 里计数，
用户完全不知道"是在线没连上"还是"这词确实没有音标"。

### 原因三：没有并发保护 + 提示不去重 → 连点 3 次变 3 条提示

- `runPhoneticFetch` 没有运行中的锁。第一次还在跑（1000 个词要逐个查）时再点，
  会真的再起一个任务，出现多个进度弹窗。
- `toast()` 不去重，相同的文案会一条条叠上去，最多叠 3 条。

---

## 要做的修改

1. **`toast()` 去重**
   同一条文案在显示期内再次触发时，重置它的计时器而不是新加一条。
   ```js
   // 伪代码
   const same = [...root.children].find(el => el.dataset.msg === msg);
   if (same) { 重置定时器; return; }
   ```

2. **`runPhoneticFetch` 加并发锁**
   模块级 `let phoneticRunning = false;`，进入前判断、退出时复位；
   运行中把按钮禁用，避免重复点击。

3. **结果要说明原因**
   提示改成能区分情况，例如：
   - `离线补上 42，在线补上 0，仍缺 53（离线词典无此词，且当前无法联网）`
   - 在线开关关着时说清楚"可以打开「联网时补充音标」再试"

4. **在线查询失败要熔断**
   连续若干次失败（比如 5 次）就停止在线尝试，把剩下的直接算作"离线也缺"，
   避免每个词都重试 3 次 × 12 秒超时，几十个词能耗上好几分钟。

5. **（可选）词库页按「无音标」筛选**
   让用户能一眼看到哪些词没音标，逐个手动补。
